## Source handling

Discord exposes GIF uploads as attachments and can deliver picker shares or link unfurls as GIFV video embeds. Embed fields and attachment availability can vary. Discord's October 2026 update also documents a picker provider change. The extension examines approved CDN fields supplied by Discord and exact approved media links a user posted. A Tenor or Giphy landing-page link can prompt one bounded re-fetch of the original Discord message after unfurl. Pai does not fetch the landing page, guess a media URL, or use either catalog API. A link without a supported embed or direct asset is unavailable. Signed attachment URLs can be refreshed from the same Discord message. [Discord message and embed fields](https://discord.com/developers/docs/resources/message) · [Discord GIF picker](https://support.discord.com/hc/en-us/articles/360021235192-Sending-GIFs-on-Discord) · [Discord picker update](https://discord.com/blog/discord-patch-notes-october-6-2026) · [Tenor media formats](https://developers.google.com/tenor/guides/response-objects-and-errors) · [Giphy media formats](https://developers.giphy.com/docs/api/schema/image-object/)

The worker uses the existing HTTPS host allowlist, public-address resolver, zero redirects, and 3 MiB download cap. Pillow checks animation type, frame count and cumulative pixels. The decoder samples in order and the vision request uses first and last so a vision call leaves more quota for chat. A changed or missing source fails closed. APNG and animated WebP are supported when the approved path identifies them. Silent MP4 representations use optional trusted FFmpeg/ffprobe binaries with a pinned demuxer, disabled external data references, a single video stream, pixel, duration, frame-rate, allocation, output and time limits. Unsupported, missing or audibly encoded video is skipped. Original bytes are used for delivery. No video or GIF is synthesized by the feature. [FFmpeg MOV/MP4 demuxer options](https://ffmpeg.org/ffmpeg-formats.html#mov_002fmp4_002f3gp_002fQuickTime)

## Library, selection and quotas

There is one asynchronous indexer with a queue of 12 and no backfill. Each message can contribute one accepted animation. Identical downloaded bytes reuse a description within the same channel and notice. Caption analysis includes the GIF's own authorized caption as untrusted data. It stores only a reusable description, byte fingerprint, exact source asset reference, notice and last-use time. Relevant occurrences from other authorized source messages remain available through the existing archive. The GIF library stores no media files. Video decode uses a short-lived temporary file. The cap is 256 source records per channel. The same byte fingerprint from different providers is deduplicated. Re-encodes with different bytes are not considered identical.

Contextual retrieval ranks description and same-channel source-caption overlap. An explicit /sharestyle marker on the original message can modestly boost an already relevant source, and withdrawal removes that boost. Frequent use alone does not approve an entry. The selector sees at most three IDs and descriptions, within the same response call. The P9.11 prompt is used normally when there are no candidates. The extension skips reuse for recall, explicit corrections, native-thread GIF opt-outs and flagged serious contexts. The model can also choose text on an ambiguous turn. It cannot choose a URL. A selected ID is resolved locally, the original Discord message is fetched again, the media type and bytes are checked and the access and source state are checked again before delivery. It can send the original media alone or with text. Successful delivery starts a 12-minute reuse cooldown per fingerprint. If media expires, an accompanying text reply can still be sent. A GIF-only choice may remain silent in that case.

Animation analysis has its own persistent 12-per-rolling-day cap and at least 30 seconds between attempts. It uses the existing Groq ledger and backoff, with a stricter combined route ceiling to leave request and token headroom for text. Throttled indexing can skip the current source. No extra text model call is required to choose a GIF. Inference stays on the existing Groq Free organization. [Groq rate limits](https://console.groq.com/docs/rate-limits)

Edits and metadata revisions remove prior derived rows. Embed updates refresh the Discord source and remove obsolete asset references. Message deletion, expiry, opt-out, consent changes and notice changes reuse the archive's existing lifecycle. The optional table uses foreign keys to archived messages. Backup remains encrypted and restore applies current policy and erasures.

## Safe TEST rollout and rollback

1. Leave P9.11 live until the owner approves a new private rollout and GIF opt-ins are recorded. Run the full P9.12 suite, confirm FFmpeg availability if MP4 is desired, and verify the deployment commit and golden hashes.
2. Stop the existing connector briefly and create an encrypted SQLite snapshot plus an erasure checkpoint. Test restore to a different path and keep the old configuration and P9.11 worktree. Stage the new policy privately. Use the existing one-channel connector and expected revision pin. Leave any other server untouched.
3. Start one connector with timeline-roles, Qwen first and GPT-OSS fallback. Verify direct mentions and native replies, one deliberately shared synthetic animation, one appropriate and one inappropriate GIF opportunity, and a deletion or opt-out. Check the Free ledger and keep media disabled outside the authorized feature.
4. For a code-only rollback, stop P9.12. Prepare the **latest** verified text policy with both GIF keys removed. Run the P9.12 apply-policy command against the existing database offline with that disabled-GIF policy to purge derived GIF rows. Start one exact v9.11 connector with the same archive, latest consent and prior approved engine/route flags. The optional GIF tables do not bump the golden schema version. If database recovery is required, restore the encrypted snapshot to a new path using the latest complete erasure checkpoint and current consent. Never overwrite a live archive or reapply stale opt-ins.

The development replay uses generated test fixtures and the approved Free provider to inspect actual output. It does not validate Discord's live picker or establish that the model will select a GIF naturally in every group.
