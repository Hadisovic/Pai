# P9.14.1 conversational refinement

Base is [P9.14 draft #50](https://github.com/Hadisovic/Pai/pull/50) at `9c582054bf89b728d0aea85e3090746bbb37bf38`. The golden `v9.11` runtime, instructions, character card, native roles, route order and sampling remain frozen.

## Independent assessment

1. The strongest release blocker is an integration gate. P9.14 excludes all replies from receipt storage whenever P9.13 is active. P9.13 also tracks social influences only in process memory, so removing the condition alone would let restored output bypass social consent and withdrawal. Store only the exact notes used, as a fingerprint and source links beside the existing receipt. Require current corroboration for the original author and the new recipient, and invalidate on evidence deletion or correction. Historical authority stays with the original human sources. [SQLite foreign-key behavior](https://www.sqlite.org/foreignkeys.html)
2. The P9.11 snapshot shows an unproductive refusal of a fictional bedtime story and several choice-game evasions, including a participant having to ask again. In other turns, the same participants got jokes, absurd stories and playful third options. Some evasions are part of the voice they enjoy. One incomplete reply is observable without a recorded finish reason. The old renderer can drop unsupported self-claims and tool claims, and has no generic rule requiring refusal of fiction. Quoting the audit prompts verbatim to a provider would exceed the authorized review. Use invented matched sessions with the conversational setup and follow-up intact. [DRInQ pragmatic reasoning benchmark](https://aclanthology.org/2026.acl-long.1597/)
3. Several answers confused model identity, physical capability and playful premises. The deterministic P9.14 matcher covers direct formulations. Supply a compact block of verified facts on clearly self-referential indirect turns or verified follow-ups only. Facts describe running capabilities and leave fictional birthday, pronunciation and relationships open. Test that ordinary banter has identical provider inputs.
4. P9.14 deals with exact native references. The review also exposed a different problem when a member has an indirect reference and no Discord link. Prefer bounded SQLite retrieval with explicit recall intent, current speaker and existing provenance over automatic profile extraction. A narrow cross-language vocabulary can improve candidate recall where it preserves the topic. Assistant output stays outside searchable factual evidence. [LongMemEval](https://arxiv.org/abs/2410.10813) · [SQLite FTS5](https://www.sqlite.org/fts5.html)
5. Three unanswered messages predated the speaker's authorization. Two other messages were absent from the archive during a logged Gateway interruption, including one addressed to Pai. A gap-repair task is warranted, with a durable channel cursor, REST permission and consent rechecks, bounded pagination, idempotent ingestion, and explicit no-reply semantics for backfill. This work does not change reconnect behavior. [Discord Gateway resume](https://docs.discord.com/developers/events/gateway) · [Discord history endpoint](https://docs.discord.com/developers/resources/message)

The existing SQLite and P9.13 evidence model avoid a second transcript. P9.14's comparison of Mem0, Graphiti and TomoriBot remains applicable. Reusing their storage stacks would add dependencies or processing outside Pai's current authorization model. This slice reuses only the existing local infrastructure.
