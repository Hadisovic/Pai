## Research and alternatives

- Use exact reply links as the first disentanglement signal. Chat exchanges form overlapping reply graphs, and a recent linear window can mix conversations. Measure a verified anchor, an intervening correction and a distractor together. [Conversation disentanglement](https://aclanthology.org/P19-1374/)
- Test information updates, temporal relevance and abstention across sessions, including assistant-side continuity. The published benchmarks do not directly measure this Discord friend's group. [LongMemEval](https://arxiv.org/abs/2410.10813) · [LoCoMo](https://arxiv.org/abs/2402.17753)
- Evaluate pragmatic interpretation with matched turns whose preceding context changes. A single refusal score would conflate fiction, serious danger, playful choices and impossible tools. [DRInQ](https://aclanthology.org/2026.acl-long.1597/)
- Existing SQLite FTS5 provides indexed candidates and BM25. Mem0's Apache-licensed library can run locally with a vector store, but its defaults include an external embedder. Graphiti's Apache-licensed temporal facts and explicit updates are worth borrowing as a design idea. A graph service and extraction pipeline are extra dependencies and additional processing. TomoriBot's AGPL Discord project demonstrates separated personas and memory, with a wider server and tool surface. On 2026-11-25 the project selected existing SQLite and provenance hooks for local deployment, erasure simplicity and zero extra inference. No third-party code was copied. [SQLite FTS5](https://www.sqlite.org/fts5.html) · [Mem0 defaults](https://github.com/mem0ai/mem0/blob/main/docs/open-source/overview.mdx) · [Graphiti](https://github.com/getzep/graphiti) · [TomoriBot](https://github.com/Bredrumb/TomoriBot)

## Proposed memory and identity

Keep working context anchored to Discord's message relationships. Keep episodic and semantic candidates in the existing archive with speaker, time and provenance. Resolve direct links first, then established references and scoped retrieval. Evaluate corrected facts by showing old and new statements together. Broader paraphrase or cross-language retrieval needs independent evidence before adding a provider or downloaded model. Keep P9.13 as the separate consented store for reversible group meanings. An unverified joke or reaction stays contextual.

Identify Pai as the Discord companion made by the human project developer under the public GitHub handle Hadisovic. The repository owner and authorship corroborate the owner's attribution. A pronunciation and an official birthday are unverified. Allow harmless social play around birthday questions. Answer literal identity, build, configured model, media and archive questions using current facts only. Keep identity answers out of unrelated conversational turns.

For assistant continuity, keep only the delivered message ID, a content digest, the human request and verified supporting source IDs. Recover a native parent using the existing Discord read path, scope and content confirmation. Store no duplicate assistant text. Cap receipts and retain them only while all dependencies survive. Exclude social-derived or media replies from the first recovery path. Those use distinct eligibility and invalidation rules. No backfill or widening of permissions.

For future diagnostics, correlate one ephemeral request span with provider attempts and Discord delivery. Record route, fallback reason, timings, token totals, completion finish reason when supplied, pruning counts and outcome. A private short-lived store can optionally retain selected source IDs tied to the same consent and erasure lifecycle. Avoid prompt or output logging. Keep instrumenting protected providers or storing additional private data behind its own review.

## Implemented boundaries

The first slice adds local identity routing and colloquial version recognition. Direct creator, default model, fallback and archive answers are resolved from stable project attribution and current policy/routes. Pai stays in the model path for ordinary roleplay and can still treat a birthday as a social premise. Explicit language settings carry into the new identity answers.

Native branch focus applies when a verified assistant anchor exists. It keeps the anchored branch, its relevant intervening replies and unthreaded context. A bare ping to a verified human parent containing an existing recognized self-harm taunt gets a short clarification through the Gateway. Neither extension edits the timeline builder, character card, native role encoding, prompt instructions or provider sampling.

Assistant receipts are off by default. The `assistant_continuity_opt_in` policy key enables them in a timeline engine after approved rollout. They cover eligible text-only replies with a native delivery link and no inherited assistant answer. Each channel keeps up to 192 receipts, with at most 32 source links per receipt. Recovery is one hop and uses Discord's existing parent resolution and history authorization. A receipt is omitted when media or social learning is active. Human source edits, deletion, retention, member withdrawal and policy notice changes invalidate receipts. The table does not change the archive schema version. No assistant completion becomes searchable human evidence. Existing conversations receive no backfill.

If rollout is approved, first review the private notice and restore procedure, verify the encrypted pre-rollout backup, and smoke-test in the authorized TEST channel. To roll back, stop the candidate and remove the new key from the private policy. Apply the current policy from P9.14 while disconnected to remove receipts and preserve currently authorized messages. Restart the golden pin from its isolated checkout after verifying current scope and erasures. Follow the existing [setup and privacy controls](SETUP.md).
